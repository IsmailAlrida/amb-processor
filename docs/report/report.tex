\section{RTL And Logisim Overview}

We implemented an optimized version of the ISA in verilog, and bundled with the python-based assembly simulator with bundled waveform viewers and an icarus verilog runtime to run the CPU verilog and verify the inner workings. It comes fully equipped with a text editor, simulator based on hardware, and is on github.

For the love of the game, we also implemented in parallel the origina ISA in logisim, but we could not complete it in time. 

All in all, we successfully ran the bench mark 

\begin{figure}
    \includegraphics[]{"writing0x19(Rb)to0x200(alures)dmem.png"}
\end{figure}

From the ISA, R_a is the destination register, however in STOR commands it is used to dump data in Ra 
at the memory location specified by the ALU result. 

Operand A in the ALU comes from a direct exposure of MEMOFF from the reg file when doing memory ops and it was zero hence the operand A waveform was 0.
however operand B is the zero extended immediate (unsigned) was set to directly address 0x200. Since memory address for storing is calculated as MEMOFF + imm8 -> imm28
the result of the ALU at this clock cycle would then be the address of the written data. The sum, 0x19, held in Ra, was only written when the data memory flag was enabled.
